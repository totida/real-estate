# 부산 아파트 매물 브리핑 봇 — 작업 기록

네이버 부동산에서 부산 7개 단지의 25~26평 **매매** 매물을 매일 조회해,
단지별 브리핑 메일(신규·가격 변동·사라짐·최근 7일 변동·현재 매매 목록)을 보내는 봇.
안드로이드 폰의 Termux에서 돌린다.

## 1. 감시 대상

| 단지 | 단지번호 |
|---|---|
| 서면아이파크1단지 | 119101 |
| 서면아이파크2단지 | 119102 |
| 롯데캐슬 인피니엘 | 158511 |
| 대연양우내안애퍼스트 | 125376 |
| 대연푸르지오클라센트 | 133976 |
| 양정포레힐즈 스위첸 | 131691 |
| 연산더샵 | 112331 |

- 단지번호는 `fin.land.naver.com/complexes/<번호>` 주소에서 확인한다.
- 평형: **공급면적 기준 25~26평** (`"pyeong": [25, 26]`).
  흔히 "25평형"이라 부르는 전용 59㎡ 타입이 단지에 따라 공급 26평으로 계산돼서 26평까지 포함했다.
  (예: 서면아이파크2단지 86.23/59.78㎡ → 26평, 75.24/52.6㎡ → 23평은 제외)
- 거래 유형: **매매만** (`"trade_types": ["A1"]`).

## 2. 왜 이렇게 만들었나 (시행착오)

| 시도 | 결과 |
|---|---|
| GitHub Actions에서 실행 | ❌ 네이버가 해외 클라우드 IP의 land 서버 접속을 끊음 (타임아웃) |
| Claude Code 클라우드 환경 (`*.naver.com` 허용) | ❌ www.naver.com은 되지만 new/m/fin.land는 연결이 끊김 |
| 폰에서 Python으로 new.land API 호출 | ❌ 첫 요청부터 429 (TOO_MANY_REQUESTS) |
| 폰에서 m.land API 호출 | ❌ 빈 응답(`null`) |
| 폰에서 curl로 fin.land 매물 API 호출 | ❌ 429 — 브라우저가 아닌 요청을 막음 (TLS 지문 등) |
| **폰 Termux의 크로미움을 화면 없이 띄워, fin.land 지도 페이지 안에서 fetch** | ✅ 7개 단지 모두 조회 성공 |

- 결론: **한국 IP + 실제 브라우저**여야 한다. PC 없이 폰(Termux)만으로 해결.
- fin.land 매물 API: `POST /front-api/v1/complex/article/list` (지도 페이지 `/map`에서 호출해야 CORS 통과).
- 짧은 시간에 여러 번 조회하면 IP 단위로 일시 차단된다 → 하루 한 번만 조회, 429 받으면 즉시 중단.

## 3. 현재 동작

- **실행**: 매일 오전 10시 cron → `termux/run-alert.sh` → `naver_alert.py`
  - 실행할 때마다 `git pull`로 최신 코드를 자동으로 받는다.
- **메일 브리핑** (오전 10시, `mail_hours: [10]`):
  - 제목: `[매물 브리핑] 10/03 25~26평 · 신규 N · 가격변동 N · 사라짐 N`
  - 맨 위: 가격변동 통계 `상승 2 · 하락 3 · 평균 ▼1,200만 (-1.8%)` (상승·하락 합친 평균, 괄호는 평균 변동률)
  - 요약표(단지별 매물·신규·변동 ▲▼ 개수·사라짐·7일 건수), 단지 이름 → 네이버 단지 매물 목록 링크
  - 단지별: 이번 신규 / 이번 가격 변동(이전 → 현재, ▲빨강 ▼파랑, 상승·하락·평균) / 이번 사라짐
  - 🗓 최근 7일 변동 (메일을 놓쳐도 확인 가능, 7일간 상승·하락·평균도 표시)
  - 현재 매매 표: 정렬 `가격↑ → 동↑ → 층↓` (`"sort"` 설정), 처음 본 가격 대비 변동, 등록일
    - 여러 중개사가 올린 매물은 가격 아래 `중개사 N곳` 표시
    - 매물별 최근 가격 변동 1개 + "이전 변동 N건 ▾" 펼치기 (Gmail은 펼치기 미지원 → 펼쳐진 채로 보임)
  - 첨부: `매매매물_YYYYMMDD.csv` — 엑셀·구글 시트에서 동/층/가격 등 원하는 열로 정렬
    - 중개사 수, 최저·최고 호가, 중개사별 호가(`XX부동산 6억 1,500만 / OO공인 6억 2,000만`) 포함
  - 하루 한 번이라 시각 대신 날짜만 표시 (`"show_time": false`)
- **폰 알림**: 메일이 설정돼 있으면 조회 실패·메일 전송 실패만 알림.
- **판단 규칙**
  - 첫 조회 단지는 기준만 저장 (알림 없음)
  - 같은 집을 여러 중개사가 올린 매물은 한 건으로 묶음 → 대표 매물이 바뀌어도 신규로 보지 않음
  - **가격 변동은 중개사 매물(매물번호)별로 추적**: 중개사별 호가·이름을 저장하고 같은 매물번호끼리 비교
    - 모든 중개사 6억 → 한 곳 6억2천: 상승 1건 / 한 곳 5억8천: 하락 1건
    - 같은 날 여러 곳이 바꾸면 모두 기록
    - 매물을 지우고 새 번호로 다른 가격에 재등록하면, 빠진 번호와 새 번호를 짝지어 가격 변동으로 기록
    - "처음 대비"도 같은 중개사의 처음 가격과 비교
    - (처음에는 대표 매물만 비교해서, 대표 중개사가 바뀐 날 변동을 놓치고 다른 중개사 호가끼리 비교하는
      문제가 있었다 → 수정. 조회 seed 도 고정해 대표 매물이 이유 없이 바뀌지 않게 함)
    - ✅ 대표가 아닌 중개사들의 호가도 네이버 응답(`duplicatedArticleInfo.articleInfoList`)에 들어옴
      (09/30 `--check-brokers 133976` 으로 실제 확인)
  - 여러 중개사 매물의 표 가격 = **그 집의 최저 호가** (링크도 그 중개사 매물), "처음 대비"도 처음 봤을 때의 최저 호가 대비.
    아래에 `중개사 N곳 · 최저~최고` 범위와 최근 변동(바꾼 중개사 이름), 이전 변동은 펼치기
  - **상승·하락 통계는 그 집의 최저 호가가 실제로 바뀐 경우만** (한 집당 한 번, 최저가 변화 폭).
    최저가가 안 바뀐 개별 중개사 변동은 목록·이력에 `(뒤따라 내림)`, `(최저가 그대로)` 로 표시하고 통계에서 제외
    (예: 모두 6억 → A 5억8천(하락 1) → 다음 날 B 5억9천(최저가 그대로, 통계 제외))
  - 같은 매물 판단은 네이버의 묶음(대표 매물 + 같은 집을 올린 다른 중개사 매물번호)을 그대로 따른다.
    층이 비공개면 네이버가 못 묶어 같은 집이 따로 나올 수 있다
  - 사라짐 = 2번 연속 조회에서 안 보임 (거래 완료인지 단순 삭제인지는 구분 불가)
  - 층을 비공개한 매물은 네이버에서도 저/중/고층으로만 나온다 (정확한 층 알 수 없음)

## 4. 파일

| 파일 | 내용 |
|---|---|
| `naver_alert.py` | 본체 (파이썬 표준 라이브러리만, 크로미움은 DevTools 프로토콜로 직접 조종) |
| `config.json` | 단지·평형·거래유형·메일 시간·정렬 설정 |
| `termux/run-alert.sh` | cron이 실행하는 스크립트 (코드 업데이트, 로그, 알림) |
| `local.json` (폰에만) | 메일 계정 (git에 안 올라감) |
| `state/` (폰에만) | `seen.json` 매물 상태·가격 이력·변동 기록, `history.csv` 사라진 매물 |
| `~/alert.log` (폰) | 실행 기록 |

### config.json 주요 설정
```json
{
  "complexes": {"119101": "서면아이파크1단지", "...": "..."},
  "trade_types": ["A1"],          // A1 매매, B1 전세, B2 월세
  "pyeong": [25, 26],             // 공급면적 기준 평형
  "mail_hours": [10],             // 메일 보낼 시각(시)
  "show_time": false,             // 하루 여러 번 조회하면 true
  "sort": ["price", "dong", "-floor"]  // price 가격, dong 동, floor 층, pyeong 평, registered 등록일, - 는 내림차순
}
```

### local.json (폰, 비밀값)
```json
{"SMTP_USER": "보내는주소@gmail.com", "SMTP_PASSWORD": "Gmail 앱 비밀번호 16자리",
 "MAIL_TO": "받는주소1@gmail.com, 받는주소2@naver.com"}
```
- Gmail 앱 비밀번호: 2단계 인증 켠 뒤 myaccount.google.com/apppasswords 에서 발급.
- 비밀번호를 잊어도 `cat ~/real-estate/local.json`으로 확인 가능. 잃어버렸으면 새로 만들고 이전 것 삭제.

## 5. 폰(Termux) 설정 요약

1. F-Droid에서 **Termux, Termux:API, Termux:Boot** 설치 (Play 스토어 버전 X).
   Termux·Termux:API는 배터리 "제한 없음", 알림 허용. 삼성은 "절전 예외 앱"에 추가.
2. 설치
   ```bash
   pkg update -y && pkg upgrade -y        # 설정 파일 질문이 나오면 Y + 엔터
   pkg install -y tur-repo x11-repo
   pkg install -y python git termux-api cronie termux-services chromium xorg-xserver-xvfb
   git clone https://github.com/totida/real-estate.git
   cd ~/real-estate && python naver_alert.py
   ```
3. 메일: `local.json` 작성 후 `python naver_alert.py --mail-test`
4. 자동 실행 (Termux 완전 종료 후 다시 열고)
   ```bash
   sv-enable crond && sv up crond && sv status crond     # run: crond 확인
   (crontab -l 2>/dev/null | grep -v run-alert; echo "0 10 * * * $HOME/real-estate/termux/run-alert.sh") | crontab -
   termux-wake-lock
   ```
   - Termux 완전 종료: 알림창의 Termux 알림 펼쳐서 **Exit** (또는 세션마다 `exit`)
   - 재부팅 후 자동 시작: `~/.termux/boot/start.sh`에 `termux-wake-lock`, `sv-enable crond`
5. 잠금화면 상태로 둬도 된다. 단, Termux를 최근 앱에서 밀어 끄지 말고 wake lock 유지, 충전 권장.

## 6. 자주 쓰는 명령 / 문제 해결

| 상황 | 명령·조치 |
|---|---|
| 실행 기록 확인 | `tail -30 ~/alert.log` |
| 중개사별 호가 수신 점검 | `python naver_alert.py --check-brokers 133976` (한 페이지만 조회, 기록 안 바꿈) |
| 브리핑 메일 지금 받아보기 | `python naver_alert.py --mail-preview` (마지막 조회 결과로, 네이버 조회·기록 변경 없음) |
| 기록 상태 확인 | `python naver_alert.py --status` (단지별 추적 매물·가격 바뀐 매물·7일 변동) |
| 사라진 매물 기록 | `python naver_alert.py --history` (`--history 100`) |
| 메일 설정 확인 | `python naver_alert.py --mail-test` |
| cron 등록 확인 | `crontab -l`, `sv status crond` |
| cron 동작 테스트 | `* * * * * date >> $HOME/cron-test.log` 등록 → 확인 후 삭제 |
| alert.log가 아예 없음 | cron이 안 돈 것 → crond 켜기·등록 다시 |
| 429 / TOO_MANY_REQUESTS | 네이버 일시 차단 → 몇 시간 쉬기, 반복 실행 금지 |
| 크로미움을 찾지 못함 | `pkg install chromium` (tur-repo 필요), `ls $PREFIX/bin \| grep chrom` 확인 |
| 크로미움 실행 실패 | `CHROMIUM_XVFB=1 python naver_alert.py` |
| 메일 `Username and Password not accepted` | 일반 비밀번호 대신 앱 비밀번호 사용 |
| 설치 중 멈춘 것 같음 | 설정 파일 질문 대기일 수 있음 → `Y` + 엔터 |

## 7. 검토했지만 안 한 것

- **PC + Playwright**: 확실하지만 PC를 켜둬야 해서 제외.
- **국토부 실거래가 API**(data.go.kr): 실제 거래·층수까지 나오지만 인증키 필요, 신고까지 최대 30일 지연 → 사라진 매물 기록으로 대체.
- **메일 안에서 눌러서 정렬**: 메일 앱이 스크립트를 막아 불가 → 설정 정렬 + CSV 첨부로 대체.
- **네이버 부동산 앱 관심단지 알림**, **웹페이지 변경 감지 앱**: 코드 없는 대안으로 안내만 함.
